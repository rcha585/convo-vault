# Data boundaries and permitted use

Status: **normative v0.2 policy**

## Ownership classes

| Value | Meaning |
| --- | --- |
| `user-authored` | Created by the vault owner and suitable for style analysis when permitted |
| `user-work` | Produced or handled through employment/project duties; may contain confidential material |
| `third-party` | Reports, books, articles, policies or other external material |
| `conversation` | Multi-party conversation whose individual messages retain their own author roles |
| `ai-generated` | Generated by a model and not automatically accepted as the user's belief |
| `mixed` | Contains more than one ownership class and must be resolved at a finer level before training |
| `unknown` | Ownership has not been reviewed |

## Privacy classes

| Value | Default handling |
| --- | --- |
| `public` | May be shared only after provenance and licensing review |
| `private` | Local retrieval; never committed |
| `confidential` | Restricted local access; sanitize before creating generalized methods |
| `restricted` | Credentials, highly sensitive personal/company data, or legally constrained material; exclude from indexing content and all datasets by default |

## Source modes

- `external-index`: keep the original in place; store metadata, fingerprint and link.
- `snapshot`: copy a verified immutable source into private raw storage.
- `synthetic`: invented test data safe for public examples.

## Allowed-use vocabulary

- `archive`: preserve and audit provenance.
- `search`: keyword/metadata search.
- `retrieval`: supply evidence to a RAG answer.
- `summarize`: produce a cited derived summary.
- `style-analysis`: analyze expression without asserting factual truth.
- `reasoning-analysis`: analyze decisions and revisions with message-level attribution.
- `skill-derivation`: create a generalized draft method after review and sanitization.
- `training`: include in an explicitly built model-training dataset.
- `public-share`: publish the content itself, not merely the processing code.

Absence from `allowed_uses` means the use is not authorized.

## Default policy matrix

| Source class | Default privacy | Default permitted uses | Default training policy |
| --- | --- | --- | --- |
| Personal published writing | private | archive, search, retrieval, summarize, style-analysis | review-required |
| Personal conversations | private | archive, search, retrieval, reasoning-analysis | review-required |
| Employment files | confidential | archive, search | prohibited until sanitized |
| Research reports | private/third-party | archive, search, retrieval, summarize | retrieval-only |
| Credentials or secrets | restricted | archive metadata only | prohibited |
| Synthetic fixtures | public | all test/documentation uses | synthetic-only |

## Public repository boundary

May be committed:

- Import, extraction, catalog and Obsidian-writing code.
- JSON Schemas and empty templates.
- Documentation and synthetic fixtures clearly marked synthetic.
- Tests that use only synthetic or redistributable data.

Must never be committed:

- Any `vault-private*` content, local catalogs, embeddings, vector stores or generated datasets.
- Original conversations, personal writing, reports, employment files or family finance data.
- Absolute source paths, private hashes tied to an inventory, processing logs or review history.
- Credentials, `.env` files, local configuration, email exports or personal/company identifiers.

May be published only after abstraction and review:

- Generalized playbooks derived from private work.
- Skills that contain no company-specific procedures, identifiers, numbers or examples.
- Demonstrations rebuilt with synthetic data rather than redacted originals.

## Claim and resume safeguards

Every externally used claim must cite evidence and declare one of: `direct`, `corroborated`, `inferred`, `user-confirmed`, or `unverified`. AI must not increase responsibility level, invent metrics, or convert possession of a file into proof that the user performed the work. Confidential evidence may support private drafting but must not be reproduced in the output.

## Enforcement points

1. Import applies source mode, ownership and privacy from configuration; no personal folder name is hard-coded.
2. Compilers read `allowed_uses` before processing.
3. Dataset builders fail closed when policy is absent or conflicting.
4. Public-export checks scan for private paths, identifiers, secrets and non-synthetic fixtures.
5. Git ignore is a safety net, not the only privacy control.
